# Contract gaps — what a screen wants that `apps/api` does not serve

Every line here is a UI need that the served API cannot currently back, recorded instead of
worked around. The rule that produces this file is plan §18's first rejection trigger — *a number
rendered in the UI that no API response contains is a lie* — and the corollary the decoders
enforce: a field the server never emits is refused by `contract.ts`, never defaulted. So each gap
has two honest resolutions, and both are worse than the gap looking small: **the server starts
emitting a real measurement**, or **the screen stops asking**. Choosing the second is a product
decision, not a cleanup, which is why it is written down rather than taken quietly.

Ordered by what a judge would notice first.

| Screen | What it asked for | Why the server cannot answer | What would make it real |
| --- | --- | --- | --- |
| `/network` | Six overlay classes selecting something: `cycle`, `fan_in`, `fan_out`, `high_velocity_hops`, `dense_community`, `flagged` | The graph artifact stores exactly one edge flag, `self_pair` (`packages/pipeline/oxbow/adapters/warehouse/landing.py:2540`), and node flags arrive only from `community.density` and the score band. The pipeline never marks a cycle or a fan on an edge, so five of the six overlays select an empty set. | Have the rules layer write its hits onto the edges it evidence-links — R4 already names the cycle and its member transactions, so this is a projection of measurements that exist, not a new one. Until then the chips render disabled and say which flags the run stored. |
| `/network` | A subgraph at all, for the landed run | `oxbow score` builds its graph in memory for the rules layer and never persists it, so `community`, `graph_edge` and `account_membership` have no rows for a score-only run, and the landing refuses rather than copying another run's numbers in under this run's id. | Run `oxbow graph` for the same run id (or have the score stage persist its graph), then land it. Copying a neighbouring run's artifact directory is the substitution the partition key exists to prevent. |
| `/model` | `pr_curve` — the operating point drawn on a precision/recall curve | No curve points exist in `out/backtest/real40k/ablation_results.json`. `curve_point` is a stored table with no builder wired into the backtest report, and the PR curve is therefore not measurable from anything on disk. | Produce it in the backtest report layer over each fold's own test-frame predictions. The API must not compute it at read time — §02 seam 5 says the API never recomputes what the pipeline did. |
| `/model` | `brier` and a reliability curve, as headline figures | The per-fold Brier **is** recorded (40 fold/policy cells in the artifact) but `ValidationBundle` declares no field for it, and no route branch exists. The reliability curve is a different case: every fold refused calibration, so there is no measured reliability curve to draw and drawing one would be the fabrication. | Brier: declare the field and serve the recorded cells, and decide what a single aggregate over five folds means rather than averaging the distribution away. Reliability: it stays absent while calibration is refused — the honest display is the refusal reason, which now lands per score row. |
| `/model` | `shap_waterfall` — the global importance waterfall | `shap_contribution` is persisted per scored row and reaches the case workspace, but no aggregate over the run's rows is produced anywhere, and ranking features by mean absolute SHAP is a computation the pipeline owns. | Aggregate it in the scoring/publish stage beside the per-row contributions. A waterfall of run-level means is a real, reproducible artifact; a router that averages JSONB on read is not. |
| `/model` | `time` on the metrics envelope (a model-selection wall-clock figure) | The run ledger stores created/finished timestamps and stage events store `elapsed_ms`, but nothing stores or emits a *model selection* duration, so any number here would be a duration nobody measured. | Either record it where it is actually spent, in the score stage's own ledger row, or drop the panel. |
| `/model`, `/policy` | `policy_id` on the allocation envelope | The read model has no concept of the active policy: `policy` and `policy_summary` are Postgres-only tables and nothing in this build writes either, so there is no policy in effect to name. | Land a committed policy per run in the warehouse stage. Until then the queue is ranked by the allocation the backtest recorded, and the UI must not imply an operator chose it. |
| `/cases/[id]` | `status` on the case header | `CaseDetail` declares `status: CaseStatus` and the route builds one, so this is no longer a gap for reads — it is listed because it *was* the refusal that kept the workspace from opening, and the client now decodes the served shape rather than the invented one. | Nothing. Resolved by conforming the client. |
| `/model` | `overfitting` and `label_quality`, the two nested shapes | The top-level field list conforms and a served bundle decodes through twelve of its fourteen members, but `LabelQualityDecoder` here requires a `note` string and treats every sibling key as an entry, while `apps/api/schemas/validation.py` declares no `LabelQuality` class at all — so one side describes an object the other never emits, and neither the double in `src/fixtures/server-shape.fixture.ts` nor the route can settle it from the repo. | Read the route's actual response once a run has landed and make one side move to match the other. Until then `tests/unit/decision-write-contract.test.tsx` pins the refusal to these two paths, so a reconciliation that leaves them decoding cleanly turns that test red on purpose. |
| `/dev/states` | A pane-error tier reachable on the live path | `MaybeSuspense` used `meta !== null` as its liveness signal while pages used `data === null`, so a pane could not leave its skeleton without also losing its provenance rendering. Fixed by giving `Pane` a required `resolved` prop; the two signals can no longer disagree. | Nothing. If a pane ever strands again, the suspect is a page that forgot to pass `resolved`, and `tests/unit/cls-geometry.test.tsx` holds three arms of that contract. |

Two things deliberately **not** in this file, because they are not server gaps: the alert queue's
`calibration_kind='uncalibrated'` state, which the server now serves and the queue renders with
its refusal reason; and the eleven typology rules that fire on zero accounts in the scored corpus,
which is a measurement reported by the per-rule hit-rate gate and recorded in `DECISIONS.md`
(DEV-030), not a missing field.
